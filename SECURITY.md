# Security Policy

## Supported Versions

This project is currently in active development. Security fixes are applied to the latest version on the `master` branch.

| Version | Supported |
|---------|-----------|
| Latest (`master`) | ✅ |
| Older releases | ❌ |

## Reporting a Vulnerability

**Please do not report security vulnerabilities through public GitHub Issues.**

### Preferred path — GitHub Private Reporting

Use GitHub's built-in private security advisory feature:

1. Go to the [Security tab](../../security) of this repository.
2. Click **"Report a vulnerability"**.
3. Fill in the form describing the issue.

This keeps the report confidential until a fix is ready.

### Alternative — Email

If private reporting is unavailable, you can contact the maintainer directly at the email address listed on [@stianwetterstad's GitHub profile](https://github.com/stianwetterstad).

## What to Include

To help triage quickly, please provide:

- A description of the vulnerability and its potential impact.
- Steps to reproduce (proof-of-concept if possible).
- Affected component(s) (e.g. authentication, Firestore rules, Cloud Functions).
- Any suggested mitigations.

## Response Timeline

- Acknowledgement within **5 business days**.
- Assessment and initial response within **10 business days**.
- Fix timeline depends on severity.

## Disclosure Policy

We follow [responsible disclosure](https://en.wikipedia.org/wiki/Coordinated_vulnerability_disclosure). Please give us a reasonable time to address the issue before any public disclosure.
